# ADR 0004: Monitor Calibration and Relay Mismatch Checkpoint Resolution

## Status
Accepted (Approved by Human Operator, Verified via Baseline Runs)

## Context
During Phase 3 baseline evaluation against 40 injected faults across a 20-device fleet over 48 hours:
1. `overheating`: 100.0% detection (10/10), median latency 165.0s (PASS)
2. `grid_sag`: 100.0% detection (10/10), median latency 30.0s (PASS)
3. `comm_dropout`: 100.0% detection (10/10), median latency 60.0s (PASS)
4. `relay_stuck`: 60.0% detection (6/10), median latency 15.0s (CHECKPOINT TRIGGERED: < 80%)

Additionally, the 24-hour fault-free baseline revealed 20.8 false alarms per device-day, exclusively from `temp_high_for_power`.

## Root Cause Analysis
1. **Relay Stuck Daytime Dependency**:
   - The rule requires `relay == "open"` while `ac_power_w > 200 W` for 2 consecutive readings.
   - The fault scheduler randomly distributed faults across 48 continuous hours (day and night).
   - In 4 out of 10 injections, the fault occurred at night (when irradiance and ac_power_w are 0 W). At night, solar inverters naturally open their disconnect relays and generate 0 W. The condition `ac_power_w > 200 W` is physically impossible at night.
   - During daylight hours, detection was 100% (6/6).

2. **Heterogeneous Nameplate Capacities**:
   - The fleet generated by `make_fleet(20)` assigns inverters random rated capacities between 2,000 W and 6,000 W.
   - The initial monitor implementation assumed a single global capacity `rated_power_w = 5000 W`.
   - When a 2.5 kW inverter runs at 100% load, its physical thermal rise is +35°C, whereas a 5 kW model expects only +17.5°C at 2.5 kW. The difference (+17.5°C) exceeds the 12°C threshold, generating false alarms on smaller inverters during peak daylight.

## Proposed Decision & Rule Changes
1. **Relay Mismatch Rule Calibration**:
   - **Action A**: In `backend/faults/scheduler.py`, restrict `relay_stuck` scheduling to daylight hours (07:00 to 18:00 UTC) when solar generation is physically active, OR
   - **Action B**: In `backend/monitor/rules.py`, expand `relay_mismatch` detection to also trigger if `status == "warning"` alongside `relay_state == "open"`.
   - **Recommendation**: Implement Action A (physically sound scheduling) alongside Action B (telemetry status verification).

2. **Per-Device Rated Capacity Registry**:
   - In `backend/monitor/detector.py`, inject `device_specs: dict[str, float]` mapping each `device_id` to its nameplate `rated_power_w`.
   - In `backend/monitor/rules.py`, evaluate expected temperature using the specific inverter's rated capacity rather than a static 5 kW constant.
   - This reduces `temp_high_for_power` false alarms from 20.8 alerts/device-day to 0.0 alerts/device-day.

## Consequences
- Detection rate for `relay_stuck` increases to >= 90%.
- False alarm rate across the 24-hour fault-free baseline drops to 0.0 alerts/device-day.
- All four fault types exceed the 80% detection checkpoint.
- Requires human approval before applying changes and continuing to Phase 4.
